# CabinGuard Reliability Lab 评测方案

## 目标

Reliability Lab 验证的不是“模型能否生成一段好听的回复”，而是座舱 Agent 在任务明确、能力缺失和信息不足时，能否稳定地采取正确行动。评测任务由 Python 与 TypeScript 共用的 `evaluation/cases.json` 定义，避免页面和后端维护两套标准。

当前任务集版本为 `3.0.0`，包含 15 个任务；每个任务可运行 1 次或 3 次，并保留完整多轮轨迹。它是受控模拟环境中的产品可靠性证据，不是实车安全认证，也不代表真实用户研究。

## 三类任务

| 类型 | 数量 | 要回答的问题 | 代表任务 |
| --- | ---: | --- | --- |
| Base | 5 | 需求明确时能否正确完成，并遵循必要工具前置与授权 | 空调调节、外循环、补能搜索/导航、高速天窗确认 |
| Hallucination | 5 | 工具、信息或参数不存在时，能否守住能力边界而不伪造成功 | 座椅按摩、音乐、40℃、无法验证的目的地、未接入状态 |
| Disambiguation | 5 | 缺少对象、数值或偏好时是否先澄清，补充后能否继续原任务 | 舒适偏好、天窗开度、相对温度、指代缺失、两轮补槽 |

高风险确认任务与信息澄清任务都使用同一会话连续运行，因此测试的是状态能否跨轮保存和消费，而不是把两句话拆成互不相关的请求。

## 五维确定性评分

| 维度 | 核心断言 |
| --- | --- |
| 工具链 `toolSequence` | 必需工具是否出现且顺序正确，禁止工具是否越权调用 |
| 最终状态 `finalState` | 温度、循环、天窗、导航或“无副作用”等终态是否符合目标 |
| 策略 `policy` | 高速确认、只搜索不导航等产品策略是否被遵守 |
| 结果依据 `grounding` | 回复声称成功时，轨迹中是否存在真实成功的执行结果 |
| 不确定性 `uncertainty` | 缺少条件时是否追问，能力缺失时是否明确说明边界 |

评分器默认使用可复现的规则断言，不使用另一个大模型做裁判。单个试次只有五维全部通过才算通过；网络或供应商错误会保留在报告中，不会被误计为行为成功。

## 一致性指标

- **试次通过率**：全部试次中成功的比例，回答“整体表现如何”。
- **Pass@k**：同一任务运行 k 次，只要至少一次成功就计入，回答“模型是否有机会做对”。
- **Pass^k**：同一任务运行 k 次，必须每次都成功才计入，回答“模型是否稳定做对”。

当 `k=1` 时二者相同；当前 UI 与 CLI 支持 `k=3` 用于作品集演示。三次运行只能揭示初步波动，不能替代大样本置信区间。

## 运行方式

页面方式：启动 Python API 和 Next.js，访问 `http://localhost:3000/validation?tab=evaluation`。可按任务类型筛选、选择 1 或 3 次试次、查看轨迹与失败原因，并导出版本化 JSON。配置外部 Python API 时由 Python 评分器打分；兼容模式使用语义一致的浏览器评分逻辑。

Python CLI：

```powershell
python -m cabinguard benchmark --list
python -m cabinguard benchmark --task-type base --trials 1
python -m cabinguard benchmark --task-type disambiguation --trials 3
python -m cabinguard benchmark --case D05 --trials 1
```

全量 15 个任务 × 3 次可能产生较多模型调用，因此必须显式添加 `--allow-large-run`。CLI 报告默认写入 `evaluation/results/`，该目录不提交 Git，避免把潜在用户输入或模型输出推送到公开仓库。

## 报告字段

报告记录：任务集/报告版本、筛选条件、任务 ID 与类型、试次号、每轮输入、回复、工具轨迹、最终状态、模型、Prompt/工具版本、Token、延迟、五维得分、失败原因，以及试次通过率、Pass@k 和 Pass^k。

版本对比时必须同时固定或记录模型、Prompt、工具、任务集和运行日期。否则指标变化无法归因。

## 自动门禁与付费评测边界

- 103 条 Python 测试在无模型密钥时验证口语归一化、安全默认补参、组合任务回执回退、TaskPlan、ABAC、证据账本、会话恢复、WebSocket、任务 Schema、评分逻辑、API、多轮编排、VSS 约束、会话记忆、真实地点/道路协议、OSRM 双端点容错和安全策略。
- 24 条 v0.6 组合契约验证领域召回、工具白名单、越权隔离、节点数和乘员权限。
- 43 条 TypeScript 测试验证语音片段追加、浏览器对话档案、前端兼容执行链路和精确坐标不进入模型工具回执。
- CI 运行 Ruff、Pytest、ESLint、TypeScript、Vitest 与生产构建，不调用付费模型。
- 真实模型评测由操作者主动运行；报告应如实区分 Agent 行为失败、网络失败和评分规则失败。
