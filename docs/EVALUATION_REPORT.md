## 结果

10 条用例覆盖空调参数、循环模式、充电站搜索、多步补能导航、高速天窗确认、降雨阻止、行驶中后备箱拦截、状态查询、模糊表达澄清和未接入能力边界。

- 第一轮完整评测：9/10。失败项为“只搜索顺路快充”缺少 `get_vehicle_state` 前置调用。
- 修复：同时收紧工具描述，并在服务端为 `search_charging_stations` 增加车辆状态查询硬前置条件。
- 定向复测：正确执行 `get_vehicle_state → search_charging_stations`，且未在用户没有要求时启动导航。
- 第二轮完整评测：9/10。行为用例均符合预期；一条空调用例因本地代理 TLS 瞬时断连返回 HTTP 502。
- 稳定性修复：模型单轮请求保留 3 次有限重试，Agent Lab 与评测客户端增加 1 次整条请求级重试。空调用例随后定向复测通过，实际工具链为 `get_climate_state → set_climate`，目标温度为 23℃。

第一轮平均端到端延迟为 3.63 秒/用例；第二轮受网络重试影响为 7.47 秒/用例。该差异说明当前主要性能瓶颈来自外部模型网络链路和多轮串行调用。

## 当前结论

修复后的 10 类行为均已观察到通过结果，说明工具选择、关键参数、安全规则和能力边界形成了可运行闭环。当前样本量仍小，且不是生产可靠性证明；正式比较 Prompt 或模型版本时，应至少重复运行多轮并报告均值、方差、P95 延迟、失败类型和 API 成本。

## 后续会话安全升级

此基线形成于浏览器提交模拟车辆状态的版本。当前 CabinGuard 已改为在 Agent Lab 与评测中先创建服务端演示会话：浏览器只提交会话 ID、用户文本和有限历史，工具从会话读取、更新模拟状态。高速天窗的首次请求会被工具层阻止并写入 2 分钟有效的待确认动作；下一轮明确确认由服务端直接恢复该动作。

升级后已重新验证：生产构建通过；服务端会话创建通过；空调调节主链路通过；高速天窗“工具层阻止 → 服务端确认 → 成功执行”链路通过。完整 10 条回归集仍应在每次模型或 Prompt 变更后重新运行并留档。

## 确定性质量门禁升级

为避免把模型随机性和 API 网络状态混入每次代码提交，项目新增独立的确定性测试层：

- 103 条 Pytest 覆盖口语归一化、安全默认补参、组合任务回执回退、Python 多轮编排、FastAPI API 形状、Pydantic 严格参数、会话恢复、真实地点/道路协议、路线步骤完整性、OSRM 双端点容错、定位同意、确认语义、工具前置、安全拦截、导航授权和结果依据。
- 43 条 Vitest 用例覆盖语音追加、对话档案、会话场景、浏览器定位、坐标隐私、路线状态、确认 TTL、一次性消费、限流、明确确认/取消优先、工具参数拒绝、读取前置、降雨与行驶拦截、导航授权和结果依据。
- GitHub Actions 在无供应商密钥的环境中执行 Ruff、Pytest、ESLint、typecheck、Vitest 和生产构建。
- `npm run check` 已在本地完整通过；Next.js 已升级至 16.3.4，当前 `npm audit` 为 0 个已知漏洞。
- 10 类 DeepSeek 行为评测没有在本次确定性重构后冒充重新运行结果；下一次有意调用付费模型时，应通过 `python -m cabinguard benchmark`（或验证中心 `/validation` 的批量测试报告页）运行并保存新的 JSON 报告。

## 位置与导航升级实测（2026-09-12）

使用 Python 一键启动器同时启动 FastAPI 和 Agent Lab 后，先通过真实 HTTP 请求创建包含上海 WGS84 坐标与 18 米精度的会话，接口正确返回 `locationSource=browser_geolocation`。随后使用默认模拟位置向 `deepseek-flash` 提交“电量不多了，找个顺路快充并导航”，4 个模型轮次产生 `get_vehicle_state → search_charging_stations → start_navigation`，最终目的地为顺义服务区超充站，路线距离 18.6 km、ETA 20 分钟、路线折线 3 个点，Prompt 版本 `3.2.0-python`，工具版本 `3.1.0-python`。

精确浏览器坐标只保留在本地会话与返回给同一浏览器的车辆状态中；发给模型的 `get_vehicle_state` 与 `start_navigation` 工具回执不包含经纬度或折线坐标。这是 v3 补能沙箱的历史实测，不代表当前 v4 普通地点真实道路能力或充电站平台接入。

## v4 普通地点与真实道路冒烟（2026-09-14）

在默认北京模拟起点调用 Nominatim 检索“昌平区政府”，随后用首个服务端候选调用 OSRM，道路服务返回约 45.9 km、38 分钟和 100 个简化折线点。新增测试以 HTTP Mock 固定验证候选坐标不会进入模型工具回执、浏览器真实位置未同意外部算路时会被阻断，以及地图供应商失败时不会生成虚假路线。公共地图结果会随数据更新，不把该距离作为长期固定 KPI。

端到端 Agent 单任务实测完成 `get_vehicle_state → search_places → plan_navigation`，返回北京市昌平区人民政府、38.7 km、32 分钟、2 条路线、8 个步骤和 29.6% 预计到达电量。复合任务“导航到昌平区政府，同时把空调调到23度并切换外循环”在 3 个模型轮次内完成 `get_climate_state → get_vehicle_state → search_places → set_climate → plan_navigation`，最终同时得到 23℃外循环和真实道路路线。以上是当次外部服务与模型结果，不等同于固定 SLA。
