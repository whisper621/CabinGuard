## 结果

10 条用例覆盖空调参数、循环模式、充电站搜索、多步补能导航、高速天窗确认、降雨阻止、行驶中后备箱拦截、状态查询、模糊表达澄清和未接入能力边界。

- 第一轮完整评测：9/10。失败项为“只搜索顺路快充”缺少 `get_vehicle_state` 前置调用。
- 修复：同时收紧工具描述，并在服务端为 `search_charging_stations` 增加车辆状态查询硬前置条件。
- 定向复测：正确执行 `get_vehicle_state → search_charging_stations`，且未在用户没有要求时启动导航。
- 第二轮完整评测：9/10。行为用例均符合预期；一条空调用例因本地代理 TLS 瞬时断连返回 HTTP 502。
- 稳定性修复：模型单轮请求保留 3 次有限重试，Agent Lab 与评测客户端增加 1 次整条请求级重试。空调用例随后定向复测通过，实际工具链为 `get_climate_state → set_climate`，目标温度为 23℃。

第一轮平均端到端延迟为 3.63 秒/用例；第二轮受网络重试影响为 7.47 秒/用例。该差异说明当前主要性能瓶颈来自外部模型网络链路和多轮串行调用。

## 当前结论

修复后的 10 类行为均已观察到通过结果，说明工具选择、关键参数、安全规则和能力边界形成了可运行闭环。当前样本量仍小，且不是生产可靠性证明；正式比较 Prompt 或模型版本时，应至少重复运行多轮并报告均值、方差、P95 延迟、失败类型和 API 成本。

升级后已重新验证：生产构建通过；服务端会话创建通过；空调调节主链路通过；高速天窗“工具层阻止 → 服务端确认 → 成功执行”链路通过。完整 10 条回归集仍应在每次模型或 Prompt 变更后重新运行并留档。

- GitHub Actions 在无供应商密钥的环境中执行 Ruff、Pytest、ESLint、typecheck、Vitest 和生产构建。
- `npm run check` 已在本地完整通过；Next.js 已升级至 16.3.4，当前 `npm audit` 为 0 个已知漏洞。
- 10 类 DeepSeek 行为评测没有在本次确定性重构后冒充重新运行结果；下一次有意调用付费模型时，应从 `/evaluation` 运行并保存新的 JSON 报告。
