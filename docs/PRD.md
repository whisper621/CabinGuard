# CabinGuard 产品需求文档（v0.7）

## 1. 摘要

CabinGuard 是一个面向智能座舱的可信协同 Agent 原型。它关注的不是“能否把一句话识别出来”，而是把一次跨域座舱请求可靠地完成为可审计的闭环：理解意图、拆解任务、检查上下文和权限、调用确定性服务、回写车辆状态，并向用户解释执行结果。

当前版本以“一个座舱主 Agent + 领域边界 + 确定性工具服务”的混合架构实现。用户面对的是一个统一助手；系统内部由主编排器协调导航、车控、媒体、充电、记忆等领域能力。需要推理和决策的环节由 Agent 处理，需要确定性和安全约束的环节由工具、策略和状态机处理。

> 定位边界：CabinGuard 是可运行的产品原型与评测工程，不是已经接入量产车辆 CAN、真实车机账号体系或高精地图的生产系统。

## 3. 背景与问题

座舱助手天然处于多设备、多上下文和安全敏感环境中。用户的一句话常同时涉及导航、空调、座椅、车窗、媒体或车辆状态，例如：“有点闷，开一点窗，找个充电站然后导航过去。”

常见体验问题包括：

1. 口语、语气词和省略信息让单一关键词规则漏识别或误执行。
2. 同一请求跨越多个领域，若只给出文字回复，用户无法判断到底完成了哪些动作。
3. 高风险操作（例如高速开启天窗）不能仅靠模型自行决定，必须由服务端策略约束并要求确认。
4. 外部地图、媒体等服务会失败或返回不完整结果，系统必须呈现真实状态，而不是编造成功结果。
5. 对话与任务记录若不持久化，用户无法理解前后文，也无法追溯一次动作的依据。

CabinGuard 的产品命题是：在一个统一的座舱入口中，让跨域任务“可执行、可解释、可中断、可回放”，并让任何受限或失败的动作都有明确、诚实的回执。

## 4. 目标、指标与范围

### 4.1 产品目标

1. 支持自然语言和语音输入下的多意图、组合任务执行。
2. 用上下文、角色和策略控制高风险车控，不让模型绕过服务端规则。
3. 提供地图优先的任务体验：定位、路线、到达电量预测、候选路线与执行状态同屏可见。
4. 让用户可查看任务计划、工具调用结果、策略拦截和历史记录，建立对 Agent 的信任。

## 5. 用户、场景与任务

### 5.1 目标用户

| 用户 | 核心需求 | 设计原则 |
| --- | --- | --- |
| 驾驶员 | 行驶中少分心地完成导航与车控 | 高风险动作确认、短回执、可撤销/可取消 |
| 前排乘客 | 协助设置舒适性和媒体 | 依据座位和角色限制可操作范围 |
| 后排乘客/儿童同行家庭 | 安全、舒适与分区控制 | 儿童锁、角色权限和明确状态反馈 |
| 项目评审者 | 理解 Agent 是否真正执行而非只会聊天 | 提供计划、状态、工具回执和评测证据 |

### 5.2 八个体验场景

| 场景 | 典型触发 | 核心能力 | 风险控制 |
| --- | --- | --- | --- |
| 智能通勤 | “导航去公司，空调调舒服点” | 导航、舒适控制、记忆 | 驾驶员身份与参数校验 |
| 雨天出行 | “下雨了，帮我看清楚一点” | 雨刷、除雾、后视镜加热 | 车速和天气上下文 |
| 长途高速 | “高速上有点闷，开天窗” | 导航、通风、休息建议 | 高速天窗操作需确认或拒绝 |
| 低电量 | “找个能充电的地方并过去” | 电量预测、充电 POI、路线 | 电量阈值和路线可达性提示 |
| 儿童同行 | “孩子睡着了，调暗一点” | 后排舒适、灯光、儿童安全状态 | 儿童场景策略优先 |
| 接驾模式 | “我去接人，打开后备箱” | 接驾路线、后备箱、迎宾灯光 | 停车/角色条件校验 |
| 休息恢复 | “找个地方休息一下” | 服务区/POI、座椅、媒体 | 行驶状态下的安全提示 |
| 空气质量 | “车里有点闷，有异味” | 内外循环、空调、空气质量状态 | 传感器缺失时诚实降级 |

### 5.3 关键用户旅程

```text
用户口语/语音
  → 语气词归一与意图识别
  → 任务计划（多领域子任务）
  → 工具白名单、ABAC、VSS/安全策略校验
  → 导航/媒体/车控等确定性服务执行
  → 状态回写与任务回执
  → 地图、对话、证据和历史记录同步展示
```

## 6. 用户价值与差异化

CabinGuard 的差异不是“把更多按钮放进聊天框”，而是把生成式理解和确定性执行分层：

```text
请求 → TaskPlan → 工具白名单 → ABAC + VSS 策略 → 工具回执 → 状态更新 → 证据回放
```

这条链路带来四项用户价值：

1. **跨域协同**：一次表达可拆成导航、舒适、媒体等多个任务，按依赖顺序执行。
2. **安全可信**：角色、场景、车速和车辆状态由服务端校验；模型不能直接改写敏感状态。
3. **结果可见**：地图、路线、车况、任务标签和工具回执同步呈现，不以“已完成”掩盖失败。
4. **可验证可复盘**：验证中心展示任务、策略、轨迹和评测，使产品从演示型聊天界面变为可评估工程原型。

## 7. 方案与验收要求

### 7.1 系统结构

| 层级 | 职责 |
| --- | --- |
| 统一座舱入口 | 文本/语音输入、地图优先工作台、任务与历史展示 |
| 主编排器 | 归一口语、识别意图、生成任务计划、协调领域边界 |
| 领域边界 | 导航、媒体和车控等能力按工具集合与上下文隔离 |
| 确定性服务 | 路线、地理搜索、媒体、车辆状态、记忆和策略执行 |
| 可信控制层 | 工具 allowlist、ABAC、VSS 风格状态约束、高风险确认、审计回执 |

### 7.2 核心需求与验收

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| R1 | 识别含语气词、并列连接词和省略表达的请求 | 同一语义的多种口语表达进入同一任务合同；不确定参数时要求澄清 |
| R2 | 支持组合任务 | 一个请求可生成多个子任务；每一项都有独立状态、失败原因和最终汇总 |
| R3 | 保障高风险车控 | 高速开启天窗等动作必须服务端拦截或进入确认，不得仅靠前端隐藏按钮 |
| R4 | 展示真实导航边界 | 成功时展示来源、路线和距离；外部服务不可用时显示失败/降级，不虚构路线 |
| R5 | 维护会话连续性 | 新对话需明确“重置会话”语义；同一会话内对话、任务和证据可回看 |
| R6 | 可审计执行 | 每次工具调用记录允许/拒绝、输入、输出摘要、状态版本与原因 |
| R7 | 可演示媒体能力 | 可搜索可公开试听内容；无预览、网络失败或版权限制时明确告知降级状态 |

### 7.3 关键产品规则

1. 只要工具未成功返回，就不得在自然语言中宣称该动作已完成。
2. 位置只在用户授权后用于本次会话；精确坐标不应自动写入模型上下文或长期记忆。
3. 高风险操作的确认、权限和状态约束必须由后端执行，不能由提示词替代。
4. 缺少必填参数时应澄清，不得猜测档位、车窗开度、目的地或角色。
5. 外部服务失败时保留任务轨迹并提供可操作的下一步，而不是清空对话或覆盖历史。

### 7.4 已知假设与开放问题

1. 当前车控为状态沙箱，不能代表真实 ECU、车辆网关或道路安全表现。
2. 公共地图、路线和试听来源受网络、速率限制、地区与服务条款影响。
3. 当前尚未完成真实用户研究、真实模型大样本行为评测和硬件在环验证。
4. 面向量产还需要补齐车辆身份、证书/HSM、工具幂等、取消/超时/补偿、驾驶分心评估和合规审查。
