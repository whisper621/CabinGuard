## 2. Intended vs. Implemented 核查

| 公开意图 | 源码证据 | 对 CabinGuard 的启发 | 本轮真实实现 |
| --- | --- | --- | --- |
| 多意图可形成任务图 | `p1-cabin-agent` 的 StateGraph、任务 wave 与 Send fan-out | 组合任务不能只靠一问一答 | 保留 DeepSeek 多轮 Tool Calling，增加运行时执行图和组合座舱任务；没有冒充已实现 LangGraph 并行 fan-out |
| 槽位和偏好可跨轮延续 | 黑板栈、slot transfer、SQLite memory | 需要区分对话历史、偏好和执行回执 | 新增 30 分钟会话内偏好读写；写入/删除必须由本轮用户明确授权 |
| 行程形成情景记忆 | episodic memory | 记忆应来源于真实成功回执 | 成功 `plan_navigation` / `start_navigation` 才写入最近 10 条会话行程 |
| 信号与约束可声明 | signal metadata、constraint config、store validation | 页面能力与执行规则应共用数据源 | 新增 25 个 VSS 对齐信号、5 条声明式约束，并直接接入空调、天窗、车窗和后备箱工具 |
| 工具权限需要分层 | tool manifest 的黑/灰/彩权限 | UI 必须解释何时直执、确认或禁止 | 能力清单暴露 direct / confirm / blocked；System Lab 显示权限标记 |
| 执行与展示分离 | Director console、screen bus、adaptive card contract | 面试展示需要架构控制台，而非只有聊天窗 | 新增 System Lab；能力数据从 Python 注册表读取，失败时不展示伪造静态数字 |

## 3. 三视角功能发散

### 产品经理视角（5 项）

1. 将能力回答绑定运行时注册表，避免 Agent 口头夸大能力。
2. 增加会话偏好与行程回执，让多轮体验形成连续性。
3. 将“真实联网”和“车辆沙箱”在每个页面明确分层，降低演示误导。
4. 把权限拆为直执、需确认、禁止，使功能范围可被产品和安全团队共同评审。
5. 建立组合任务演示路径，以一次请求同时验证导航、舒适域和记忆。

### 设计师视角（5 项）

1. 独立的 System Lab 显示执行图、工具清单、信号表与约束卡。
2. AgentLab 增加座舱域实时状态，动作完成后页面有直接视觉反馈。
3. 用 LIVE / SANDBOX 标签表达外部服务与车辆执行的真实性差异。
4. 把约束的 reject / clamp、原因和建议放在同一张卡片上。
5. 按能力域筛选工具，降低 14 个工具同时展示的认知负担。

### 工程师视角（5 项）

1. 建立单一工具注册表并由接口动态计算数量，防止文档计数漂移。
2. 引入分段 glob 与声明式 constraint evaluator，取代散落的 if 文案。
3. 使用显式挡位信号而不是从车速推断 P/D。
4. 将导航、车辆域和会话记忆拆成执行器，保持授权边界清晰。
5. 为每条新约束和记忆权限写确定性测试，并继续保留模型行为评测。

## 4. 优先级前五与结果

| 优先级 | 功能 | 选择原因 | 关键假设 | 状态 |
| --- | --- | --- | --- | --- |
| P0 | VSS 对齐信号 + 声明式约束 | 同时提升工程可信度、可解释性和扩展性 | 面试官更看重可执行规则而非静态架构图 | 已实现：25 信号、5 规则 |
| P0 | System Lab 架构控制台 | 让复杂度、边界和证据一眼可见 | 招聘展示需要 2–3 分钟内建立系统全貌 | 已实现：运行时动态接口 |
| P0 | 座舱设备域扩展 | 解决“只有问答、导航和风险判断”的功能单薄问题 | 车窗/座椅/灯光/除霜能代表跨域座舱编排 | 已实现：统一严格工具 |
| P1 | 会话偏好与行程记忆 | 展示 Agent 连续性，同时控制隐私范围 | 会话级记忆足以验证价值，不必先做账户持久化 | 已实现：明确授权、30 分钟 TTL |
| P1 | 组合任务与执行图 | 将工具数量转化为可讲述的任务完成能力 | 多轮 Tool Calling 能先验证串行依赖 | 已实现串行循环与可视化；并行 DAG 留待后续 |

## 5. 本轮代码落点

- `backend/cabinguard/signals.py`：VSS 对齐目录、分段 glob、声明式约束与裁决。
- `backend/cabinguard/tools.py`：14 个注册工具，新增统一座舱设备控制和能力查询。
- `backend/cabinguard/memory.py`：偏好与行程会话执行器。
- `backend/cabinguard/capabilities.py`：工具、信号、约束、集成与执行图的唯一能力清单。
- `src/app/system-lab/`：架构与能力控制台。
- `src/app/agent-lab/AgentLab.tsx`：座舱状态、组合任务和 System Lab 入口。

## 6. 没有冒充已完成的部分

- 没有复制或引入 `p1-cabin-agent` 源码，也没有声称 CabinGuard 使用 LangGraph。
- 目前是单 Orchestrator Agent，不把工具、规则或评测器包装成多个 Agent。
- 组合任务通过模型多轮循环串行执行，尚未实现依赖 DAG 的并行 fan-out。
- VSS 路径是语义对齐层，不是 OEM DBC、CAN 信号或量产 Vehicle API。
- 会话记忆不持久化到账号；车辆动作只更新沙箱状态。

## 7. 下一阶段建议

1. 用 WebSocket 生成 10 Hz 车辆信号流，验证动作过渡、冲突和超时。
2. 增加可取消的后台任务、幂等键与异步动作回执。
3. 将组合请求编译成带依赖边的显式执行计划，并比较串行与并行延迟。
4. 为乘员、主驾、访客和儿童建立身份/区域权限矩阵。
5. 用 5–8 名目标用户做驾驶分心与风险提示可用性测试，再决定量产交互形态。
