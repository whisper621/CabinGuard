# CabinGuard Reliability Lab 升级决策

> **历史升级决策。** 文中早期任务数量和计划不代表 v0.8 当前状态；请以 [CURRENT_STATUS](CURRENT_STATUS.md) 为准。

## 目标与成功标准

本轮目标不是增加“看起来很多”的工具，而是把 CabinGuard 从一次性 Demo 升级为可以重复验证 Agent 可靠性的产品资产，服务于 AI 产品经理、智能座舱产品经理和具身智能产品经理面试。

成功标准：

- 能区分正常任务、能力缺失和意图歧义；
- 能复现两轮以上的确认、澄清和执行轨迹；
- 不只判断最终文案，还检查工具顺序、状态、副作用、策略和结果依据；
- 能对同一任务重复运行并报告一致性；
- 评测任务、版本、模型、Prompt、工具、Token 和延迟可导出留档。

## 产品三角色发散

### 产品经理视角

1. **三类可靠性任务集**：Base、Hallucination、Disambiguation 分别验证完成、能力边界和歧义处理。
2. **一致性记分牌**：用 Pass^k 与 Pass@k 区分“偶尔会做”和“稳定会做”。
3. **版本对比实验**：保存模型、Prompt、工具版本，比较每次改动的收益与回归。
4. **成本护栏**：限制全量一致性评测，预估调用次数与 Token。
5. **失败类型闭环**：把失败归类为工具、策略、状态、澄清、依据或网络问题。

### 产品设计视角

1. **轨迹时间线**：按用户消息、模型回复、工具和状态变化还原全过程。
2. **任务类型筛选**：一键查看基础、幻觉和歧义任务的差异。
3. **试次稳定性胶囊**：每条任务直接显示 3 次运行中哪些成功、哪些失败。
4. **失败解释卡片**：把“失败”翻译为可行动的具体原因。
5. **面试演示模式**：默认只运行一组任务，控制成本并突出一个核心观点。

### 工程师视角

1. **跨语言共享任务 Schema**：JSON 同时供 Python 评测器与 TypeScript 页面读取，避免两套用例漂移。
2. **确定性轨迹评分器**：在 Python 中对工具顺序、最终状态和策略逐维评分。
3. **多轮任务运行器**：同一服务端会话中继续确认或补充槽位。
4. **一致性聚合器**：按任务聚合试次并计算 Pass^k、Pass@k 与均值。
5. **Agent 适配器接口**：后续可接其他模型或公开 benchmark，而不污染产品工具代码。

## Top 5 优先级

| 排名 | 功能 | 影响 | 工作量 | 风险 | 选择理由 |
| ---: | --- | --- | --- | --- | --- |
| 1 | 三类任务集 | 高 | 中 | 低 | 直接证明对 Agent 不确定性与能力边界的理解 |
| 2 | 多轮任务运行器 | 高 | 中 | 中 | 把确认和澄清从单轮文案升级为真实状态机验证 |
| 3 | 五维确定性评分 | 高 | 中 | 低 | 让评测不依赖主观查看回复，结果可解释 |
| 4 | Pass^k / Pass@k | 高 | 中 | 中 | 展示一致性意识，避免用一次成功冒充可靠性 |
| 5 | 轨迹与版本化报告 | 中高 | 中 | 低 | 便于复盘、简历量化和模型/Prompt 对比 |

关键假设：任务类型能代表当前产品风险；确定性断言足以覆盖主要失败；3 次重复能用于演示一致性概念，但不能代替大样本统计。

## 本轮不做

- 不机械扩展到数十个工具；工具广度不能替代策略和评测深度。
- 不复制外部项目代码、任务数据或评分实现。
- 不默认启用 LLM-as-a-judge，避免评测器本身不可复现且产生额外成本。
- 不把模拟用户包装成真实用户研究。
- 不声称 3 次运行可以证明生产可靠性。
