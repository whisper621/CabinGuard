# CabinGuard v0.8 用户研究执行方案

> 状态：**研究方案已完成，尚未招募和执行。** 本文用于产生真实用户证据，不包含虚构访谈结论。建议样本 8–12 人。

## 1. 研究目标与判定标准

验证三件事：驾驶用户能否理解并完成跨域座舱任务；主动建议与安全确认是否恰当而不打扰；Driver Mode 与 Validation Mode 的信息分层是否清晰。

| 指标 | 定义 | v0.8 目标 |
| --- | --- | ---: |
| 核心任务完成率 | 无主持人代操作且达到预期车辆/路线状态 | ≥ 80% |
| 首次成功率 | 首次表达后无需改写即可进入正确计划 | ≥ 70% |
| 严重误执行率 | 执行了用户未授权的写操作 | 0% |
| 安全提示理解率 | 能复述为什么确认/阻止 | ≥ 80% |
| 主动建议接受意愿 | 评分 4–5（5 分制）的参与者比例 | ≥ 60% |
| 单任务完成时间 | 从说出目标到理解结果的中位数 | ≤ 45 秒 |
| SUS 可用性 | 10 题标准 SUS | ≥ 70 |

## 2. 参与者与角色

招募 8–12 位最近半年每周至少驾驶一次的用户：至少 3 位经常使用车载导航/语音，至少 2 位有儿童同行经验，至少 2 位使用新能源车。排除直接参与 CabinGuard 开发的人。记录年龄段、驾驶频率、车型类别和车机语音使用频率，不采集身份证、车牌或精确住址。

研究角色：1 名主持人负责知情同意和情境提示；1 名观察员只记录行为与原话；参与者以驾驶员身份操作。若只有一名研究员，可录屏后补标，但必须先取得同意。

## 3. 测试条件

- 固定代码提交、浏览器版本、Python/Node 版本、模型请求名与 `resolvedModel`。
- 使用桌面车机尺寸或实际中控屏等比例窗口；不在真实行驶车辆中测试。
- 先验证 FastAPI、Next.js、地图和模型服务健康；每位参与者使用全新匿名浏览器配置档。
- 主持人不得讲解按钮位置；任务失败后最多追问“你现在会怎么做？”，不提供具体操作答案。
- 录屏、音频、观察笔记分别征得同意；参与者可随时退出并要求删除材料。

## 4. 场景任务与预期结果

每位参与者执行 6 个核心任务，另从 2 个扩展任务中随机选 1 个，以降低顺序学习效应。任务顺序采用拉丁方轮换。

| ID | 起始条件 | 给用户的场景描述 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- | --- |
| U01 | 智能通勤、默认位置 | “你要去昌平区政府，车里偏热，还想听轻音乐。” | 用户自行用语音或文字表达组合目标 | 生成导航、23℃温控、媒体三项任务；逐项回执，不漏项 |
| U02 | 雨天场景 | “下雨起雾，想让视野清楚。” | 用户自行表达，不提示工具名称 | 自动雨刷、前后除霜、后视镜加热正确执行；不得开天窗 |
| U03 | 高速场景 | “你想把天窗打开一半。” | 发出请求，阅读提示，再决定确认或取消 | 系统不立即执行；参与者能解释风险与确认含义 |
| U04 | 低电量场景 | “电量不多，找一个充电点。” | 先只搜索，再决定是否导航 | POI 来源与枪位未知边界清晰；只有明确导航后才启动路线 |
| U05 | 默认场景 | “让系统以后记住你喜欢 22℃。” | 查找偏好入口、授权、下达记忆，再撤回 | 未授权前不长期保存；授权后可查看；撤回后删除 |
| U06 | 任意场景 | “任务发出后立刻改变主意。” | 提交组合任务并点击取消 | UI 提供取消；后端状态显示 cancelled，取消后不再发起新工具 |
| U07 | 空气质量（扩展） | “车内空气变差，但你尚未主动操作。” | 观察并决定是否接受建议 | 系统只展示建议；未点击不改变车辆；接受后经过正常执行链 |
| U08 | 访客身份（扩展） | “尝试执行驾驶员专属动作。” | 切换访客并发出请求，再去验证中心查原因 | 服务端 ABAC 阻止；Driver Mode 给出简短原因，Validation Mode 有完整证据 |

## 5. 单任务记录格式

每个任务都按以下结构记录：

1. 测试目标：对应 U01–U08 的一个具体假设。
2. 起始条件：场景、角色、定位授权、偏好授权、网络状态和代码提交。
3. 用户输入：保留原始口语及语音识别文本，二者分列。
4. 行为步骤：首次点击、改写、返回、确认、取消和误触。
5. 实际结果：任务状态、车辆状态、工具轨迹、耗时和错误。
6. 预期对照：通过、部分通过、失败；失败必须归入产品理解、识别、编排、策略、工具、外部依赖或界面反馈。
7. 追问：让参与者复述系统做了什么、为什么、下一步会怎么做。

原始数据模板位于 `evaluation/user_research_results_template.csv`。

## 6. 访谈提纲

任务后逐项询问：

- 你认为系统刚才完成了哪些事，哪些没完成？依据是什么？
- 哪个提示最让你放心，哪个最打断你？
- 主动建议出现的时机合适吗？如果在真实驾驶中，你希望怎么关闭或延后？
- 你是否理解“偏好保留 90 天”和“撤回并删除”？什么信息绝不能被保存？
- 当路线或充电信息标注为公共数据/未知枪位时，你会如何决策？
- 你在主页面是否看到不必要的研发信息？验证中心是否能解释问题？
- 如果只能改一处，你最希望改什么？

## 7. 同意、隐私与删除

开始前朗读并确认：“这是不连接真实车辆的研究原型。测试可能记录屏幕、语音和操作，但不采集账号密码、车牌、精确住址。你可以跳过问题、随时退出，并在研究结束后 30 天内要求删除原始记录。”

参与者编号使用 `P01–P12`。精确定位一律使用预设模拟点；若误授权真实定位，报告只保留“授权/未授权”和精度区间，不保存坐标。研究原始文件与公开作品集分离，公开报告只展示聚合指标与去标识引语。

## 8. 分析与发布门槛

两名研究者独立标注严重问题（导致危险理解、未经授权写操作、无法退出）和一般问题（效率、文案、布局）。出现任何严重误执行时停止扩招、保存证据并修复；复测通过前不得以总体完成率掩盖。少于 8 位参与者时只作为探索性结果，不使用显著性语言。

最终研究报告必须包含：样本画像、任务级完成率、中位耗时、SUS、主动建议接受/关闭原因、问题清单、原始证据索引、已修复/待修复状态和局限性。
