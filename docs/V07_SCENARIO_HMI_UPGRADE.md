# CabinGuard v0.7：场景能力与地图优先 HMI 升级报告

> 交付日期：2026-09-15。本文只记录仓库中已经实现且可验证的能力；未接入真实车辆、实时路况或整曲版权的部分会明确标注。

## 1. 为什么升级

v0.6 已具备真实地点检索、道路算路、跨域任务图、安全策略和证据追溯，但主界面同时长期展示遥测卡、座舱卡、地图、路线结果和运行态，导致地图被压缩；可体验的车身和娱乐任务也偏少。v0.7 的目标是同时修复两个问题：

1. 从“能力列表”升级为能一键复现的座舱场景；
2. 从“后台仪表盘”升级为地图优先、按需展开的车机 HMI。

## 3. 页面布局

主页面只保留一个操作入口，并采用“固定信息—空间画布—上下文抽屉”三级信息架构：

- 顶部状态带只展示车速、电量、温度、天气、空气与安全六类高频信号；
- 地图占据主要空间，路线摘要、环境感知与当前媒体以小型浮层呈现；
- 底部 Dock 固定场景、温控、语音、音乐、车辆和路线六个高频入口；
- 场景、车辆设备和详细路线使用互斥抽屉，关闭后立即恢复完整地图；
- 右侧主 Agent 保留对话、任务图、回执、安全和历史，面向面试演示解释“为什么执行或阻止”。

小屏下页面回落为上下布局，地图和 Agent 不并排挤压；地图内部 Dock 可横向滚动，抽屉宽度不超过可视区域。

## 4. Agent 与确定性工具分工

```text
中文语音 / 文本
  → 主 Agent：理解目标、编译跨域 TaskPlan
  → 导航 / 媒体领域：外部检索与结果选择
  → 策略核：工具白名单 + 乘员 ABAC + 前置状态 + VSS 约束
  → 确定性工具：写入车辆沙箱或媒体状态机
  → 状态版本 + Trace + SQLite 证据回执
```

多 Agent 不等于多模型。当前一个 DeepSeek 客户端承担自然语言推理；导航与媒体是可独立版本化、隔离工具和外部依赖的领域 Agent 边界。车门、空调、雨刷等确定性动作不额外包装 LLM。

## 5. 关键安全设计

- 开门前强制读取车辆状态；行驶中或非 P 挡拒绝开启，后排儿童锁开启时拒绝对应后门；满足条件后仍需一次性用户确认。
- 充电口仅在 P 挡允许开启。
- 四窗批量控制先校验全部目标，任一约束不通过时不会形成半完成状态。
- 模型提供的 `confirmed=true` 不构成授权；只有服务端待确认记录与下一轮明确“确认继续”才会恢复动作。
- “现在播放的是什么歌”编译为只读媒体状态，不会误触发新播放。
- 没有成功工具回执时，回复依据校验器禁止声称“已经完成”。

## 6. 真实能力边界

| 能力 | 当前性质 | 不应对外声称 |
| --- | --- | --- |
| 地点与道路 | 真实公共服务请求 | 实时路况、车道级导航、公共服务 SLA |
| 当前位置 | 浏览器明确授权后真实 | 默认自动获得所有定位权限 |
| 音乐 | 真实目录元数据与 30 秒试听 | 拥有整曲版权、接入车载音乐账号 |
| 车辆动作 | 带策略和回执的数字车辆沙箱 | 已接 CAN、ECU 或能控制真实车辆 |
| 乘员身份 | 演示 ABAC 角色 | 量产账号认证或硬件可信身份 |

## 7. 面试演示建议

1. 在“智能通勤”场景发送导航 + 空调 + 音乐任务，展示主 Agent 如何拆出跨域任务图。
2. 在“雨雾安全”场景展示自动雨刷、前后除霜和后视镜加热连续执行。
3. 在“低电补能”场景展示候选站、道路路线和到达电量，而不是只展示聊天回复。
4. 在“临时上下客”场景打开右后车门，展示服务端一次性确认；切到“儿童乘车”重复操作，展示儿童锁硬拒绝。
5. 打开验证中心，沿 TaskPlan、ABAC、VSS 约束、工具回执和状态版本解释结果。

## 8. 后续量产化工作

本版本已经适合作为可运行作品集，但不等于量产车机。下一阶段优先级是：接入有 SLA 的国内地图与媒体服务、增加语音唤醒/打断、多设备幂等键与并发冲突恢复、补充真实用户可用性数据，并将车辆沙箱适配器替换为 OEM 授权的车端服务契约。
